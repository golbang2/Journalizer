# Journalizer

**배포 주소**: <https://journalizer-web.onrender.com/>
(무료 서버라 첫 접속 시 깨어나는 데 시간이 걸릴 수 있다.)

영수증 이미지·PDF와 은행·홈택스 자료를 읽어 회계 분개 초안을 만들고, 사람이 검토·수정·확정한 뒤
계정별원장과 엑셀로 내보내는 서비스다.

1. 영수증·자료를 올린다.
2. 구조화된 영수증 데이터를 추출한다.
3. 계정과목과 분개를 추천한다.
4. 검토자가 초안을 확인하고 수정한다.
5. 확정·저장하고 내보낸다.

**원칙**: 회계 담당자의 신뢰가 우선이다. 자동화는 근거를 설명할 수 있어야 하고, 확정 전에 수정할 수
있어야 하며, 확정한 작업은 되돌리고 추적할 수 있어야 한다.

## 저장소 구성

```text
Journalizer/
├── backend/              # FastAPI + Pydantic + SQLAlchemy
├── frontend/             # Next.js + TypeScript + React
├── ocr_standalone/       # 웹 앱과 분리된 Spyder용 OCR 실험 (자체 README)
├── streamlit_prototype/  # 단일 사용자 기능 흐름 프로토타입 (자체 README)
└── test.cmd              # 백엔드 문법 검사 + 프론트엔드 lint/build
```

## 빠른 시작

백엔드 (`http://localhost:8000`):

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

프론트엔드 (`http://localhost:3000`):

```powershell
cd frontend
npm install
npm run dev
```

브라우저는 프론트엔드의 `/api/*`만 호출하고 Next.js가 이를 백엔드로 넘긴다. 백엔드 주소가
`http://localhost:8000`이 아니면 프론트엔드를 켤 때 `BACKEND_URL`을 지정한다.
표는 서버 시작 시 자동으로 만들어진다.

무료 서버가 절전 상태라면 첫 접속에서 서버 시작 안내를 표시하고 최대 2분간 자동으로 연결을
재시도한다. 서버가 준비되면 로그인 또는 작업 화면으로 이동하며, 2분이 지나도 연결되지 않으면
다시 시도 버튼을 표시한다. 이 재시도는 최초 로그인 상태 조회에만 적용된다.
시작 연결 테스트는 Node.js 22.18 이상에서 `cd frontend` 후 `npm run test:startup`으로 실행한다.

## 환경 변수

예시는 [backend/.env.example](backend/.env.example), [frontend/.env.local.example](frontend/.env.local.example)에 있다.

| 변수 | 기본값 | 설명 |
| --- | --- | --- |
| `DATABASE_URL` | `backend/data/app.db` (SQLite) | 운영은 PostgreSQL. 예: `postgresql+psycopg://journalizer:비밀번호@localhost:5432/journalizer` |
| `JOURNALIZER_DATA_DIR` | `backend/data` | 기본 SQLite DB 위치 |
| `COOKIE_SECURE` | 꺼짐 | HTTPS로 배포할 때 `true` |
| `CORS_ORIGINS` | `http://localhost:3000,http://127.0.0.1:3000` | 쉼표로 구분 |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI` | 없음 | 지정하면 구글 로그인 버튼이 나타난다 |
| `GOOGLE_APPLICATION_CREDENTIALS` | 없음 | Google Vision OCR 서비스 계정 키. **저장소 밖에 보관한다** |
| `RECEIPT_OCR_ENGINE` | `vision` | `claude`로 지정하면 Claude 직접 추출 경로 사용 |
| `RECEIPT_VISION_FALLBACK` | `none` | `claude`로 지정하면 규칙에 맞지 않는 영수증을 Claude로 재처리 |
| `RECEIPT_PDF_ENGINE` | 없음 | PDF에만 우선 적용되는 엔진 설정 (구버전 호환) |
| `CLAUDE_RECEIPT_MODEL` | 경로별 기본값 | 영수증 추출용 Claude 모델 |
| `VISION_OCR_CACHE_DIR` | `backend/.cache/vision` | Vision 응답 캐시 위치 |
| `AI_JUDGE` | `on` | `off`면 AI 계정 판단을 끈다 |
| `CLAUDE_JUDGE_MODEL`, `CLAUDE_JUDGE_EFFORT` | `claude-haiku-5-5`, `medium` | AI 계정 판단 모델·노력 수준 |
| `AUTO_CONFIRM` | `on` | `off`면 누락 없는 영수증도 자동 확정하지 않는다 |
| `PARSER_TIMEOUT_SECONDS`, `PARSER_MEMORY_MB`, `PARSER_CONCURRENCY` | `30`, `1024`, `2` | 업로드 파일 파서 격리 실행 제한 |
| `BACKEND_URL` (프론트엔드) | `http://localhost:8000` | Next.js 프록시 대상 |

## 작업 화면 (`/`)

첫 화면은 로그인이며, 로그인하면 4단계 작업 화면이 나온다. 회원 한 명이 회사 하나를 가지며
다른 회원의 데이터는 보이지 않는다. `/wireframe`은 설계 참고용 샘플 화면이다.

1. **회사 기준**: 회계연도, 계정(분류·기초잔액), 회사 은행 계좌, 거래처·별칭을 저장한다.
2. **자료 연결**: 영수증(PDF·이미지)을 올리면 OCR로 초안을 만든다. OCR이 실패해도 원본은
   저장되고 직접 입력으로 넘어간다. 영수증 원본 파일도 DB에 저장된다. 은행 거래내역
   (`.xlsx`/`.xls`/`.csv`)은 계좌번호·은행명으로 계좌를 판별하며, 같은 파일을 다시 올려도
   중복 저장되지 않는다. 홈택스 자료 대조도 이 단계에서 한다([아래](#홈택스-거래별-대조)).
3. **분개 검토**: 원본을 보면서 정보를 입력하면 서버가 분개와 누락 항목을 계산한다.
   금액이 같은 출금 거래를 후보로 보여 주고, 검토자가 골라 연결한다. 누락 항목이 없을 때만 확정된다.
4. **계정별원장**: 확정 전표만 반영한다. 계정별 CSV, 분개장+원장 엑셀로 내보낸다.

## 계정과 로그인

- 이메일·비밀번호(scrypt 해시)와 httpOnly 쿠키 세션을 쓴다. 구글 로그인은 선택 사항이다.
- 이메일이 같은 비밀번호 계정과 구글 계정은 자동으로 연결하지 않는다. 충돌하면 구글 로그인은
  거절되며, 기존 가입 방식으로 로그인하거나 관리자에게 소유권 확인을 요청해야 한다.
- 이전 버전에서 자동 연결된 계정은 서버가 DB를 초기화할 때 기존 비밀번호와 모든 세션을 폐기하고
  구글 로그인만 허용한다. 회사·영수증 자료는 보존된다. 이 변경을 배포할 때는 기존 서버 프로세스를
  모두 종료하고 새 버전으로 재시작한다.

### 기존 데이터 이관

회원가입·구글 로그인으로 이전 자료를 자동 이관하지 않는다. 가입 이메일은 소유권이 인증된 값이
아니므로, 관리자가 소유권을 확인한 기존 회원의 **ID와 이메일을 함께 지정**해 빈 회사로만 이관한다.

DB를 백업하고 웹 서버를 중지한 뒤 `backend` 폴더에서 실행한다. `--data-dir`는 `journalizer.db`와
`uploads/`가 있는 폴더이고, 대상 DB는 `DATABASE_URL` 또는 기본 로컬 DB다.

```powershell
python -m app.services.legacy --owner-id 123 --expected-email owner@example.com --data-dir "F:\Journalizer\backend\data"
```

이관 뒤 `journalizer.db.imported` 표시 파일이 생기며 원본은 보존된다.

## 영수증 OCR

### 기본 경로: Google Vision

PDF와 이미지(JPG/JPEG, PNG, WEBP, BMP, GIF, TIFF)는 기본적으로 Google Vision으로 처리하며
Anthropic API 키가 필요 없다. 서버를 시작하는 터미널에서 인증 파일 경로를 지정한다.

```powershell
$env:GOOGLE_APPLICATION_CREDENTIALS = "C:\path\outside\repository\vision-service-account.json"
```

- **입력**: PDF는 원본 문서, 이미지는 원본 바이트를 `DOCUMENT_TEXT_DETECTION`에 보낸다.
  암호화되지 않은 1페이지 PDF와 단일 프레임 이미지만 허용한다.
- **추출**: 글자 좌표와 필드 라벨로 날짜·금액·세액·상호·승인번호·사업자번호를 읽는다.
  금액 검산과 필수 필드 확인을 통과한 전표만 반환한다. 통화는 KRW다.
- **서식**: 광주은행·우리카드 매출전표는 전용 규칙으로 처리한다. 그 외 카드 승인 영수증은
  거래일시·금액·승인번호 등 명확한 라벨이 있을 때만 일반 규칙으로 처리한다. 서식·필수 값이
  모호한 영수증과 전자세금계산서는 검토 오류를 반환한다.
- **경고**: 다음 경우 결과에 경고를 남긴다.
  - 사업자번호가 없는 전표: 해외 결제금액 확인
  - 우리카드 전표의 부가세 공란: 세액 0원 가정 (원문 근거와 구분)
  - 체크계좌 전표: 대변 계정 검토
  - 일반 전표에서 주소 위 줄을 상호로 읽었거나 부가세를 0원으로 가정한 경우
- **검토 필요**: 품목은 추정하지 않고 계정과목은 `other`로 반환한다. PDF만으로 취소 상태를
  확정하지 않으므로 승인번호로 사용내역과 대조해야 한다.
- **캐시·호출**: 파일 SHA-256과 OCR 설정으로 응답을 캐시한다. 캐시는 전표 원문을 포함하므로
  영수증과 같은 접근 권한으로 보관한다. API 클라이언트를 재사용하고 프로세스별 동시 호출을
  4개로 제한하며, 일시적인 호출 오류만 제한적으로 재시도한다.

### 선택 경로: Claude

- `RECEIPT_VISION_FALLBACK=claude`: 규칙에 맞지 않는 PDF·이미지를 Claude Haiku 5.5로 다시
  처리한다. 추가 API 호출이 발생하며 결과에 대체 처리 경고가 붙는다. 인증·네트워크·Vision 응답
  오류는 다른 업체에 자동으로 재전송하지 않는다.
- `RECEIPT_OCR_ENGINE=claude`: 기존 Claude 직접 추출 경로를 쓴다(기본 모델 Opus 4.7).
- `RECEIPT_PDF_ENGINE`이 설정돼 있으면 PDF에 한해 우선 적용되므로, 전부 Vision으로 처리하려면
  제거하거나 `vision`으로 바꾼다.

## 홈택스 거래별 대조

**자료 연결 → 홈택스 거래별 대조**에서 사업용·법인카드 매입내역과 매입 전자세금계산서의
거래별 상세 파일(`.xlsx`, `.xls`, `.csv`)을 종류별로 올린다. 홈택스 자동 로그인/API 수집은
포함하지 않는다. 파일은 AI에 보내지 않고 열 이름과 금액 검산으로 읽는다.

### 파일 형식

| 종류 | 필수 열 | 추가로 읽는 열 |
| --- | --- | --- |
| 카드 | 거래일자(또는 승인일자), 가맹점 사업자등록번호, 가맹점명, 공급가액, 부가세, 합계금액 | 승인번호, 카드번호, 공제여부, 거래구분, 봉사료 |
| 매입 세금계산서 | 작성일자, 공급자등록번호, 공급자 상호, 공급가액, 세액, 합계금액 | 승인번호, 공급받는자등록번호, 수정사유 |

- 세금계산서는 공급자·공급받는자 뒤에 각각 상호 열이 있는 형식도 구분한다. 회사 프로필에
  사업자번호가 있으면 수취인 번호를 검증한다.
- CSV는 UTF-8과 CP949를 지원한다. 날짜는 `YYYY-MM-DD`, `YYYY.MM.DD`, `YYYYMMDD` 등 문자열을 지원한다.
- 지원하지 않는 형식: 엑셀 일련번호 날짜, 마스킹된 사업자번호, 지수 표기 승인번호, 암호화 파일,
  HTML을 `.xls`로 저장한 파일.
- 식별자는 앞자리 0을 보존하도록 텍스트로 저장한다. 알 수 없는 열 구조나 잘못된 상세 행이 있으면
  파일 전체를 거절하고 시트·행 위치를 표시한다.
- 실제 홈택스 내보내기 서식은 샘플 파일로 추가 검증이 필요하다.

### 저장과 대조

- 원본 파일과 행 위치는 회사별로 보존하며 원본 다운로드·자료 삭제가 가능하다. 같은 파일을 다시
  올리면 추가 저장하지 않는다.
- 승인번호 등 식별자가 같은 거래는 여러 파일의 출처를 모아 보여주고, 금액·공제 표시 등이
  다르면 충돌로 표시한다. 승인번호가 없는 동일 금액 거래는 자동으로 합치지 않는다.
- 사업자번호·증빙 종류·승인번호·날짜·금액이 모두 맞는 단일 영수증만 자동 대조한다. 그 밖에는
  연결 후보를 표시하고 사용자가 연결·해제한다.
- 세액 차이, 공제 판단 차이, 누락 영수증, 복수 후보, 카드·세금계산서 이중 계상 가능성,
  취소·수정 거래를 구분해 표시한다. 조회기간·검색·검토 필요 필터로 좁힌 뒤 영수증 검토 화면으로
  이동할 수 있다.
- 홈택스에 대응 자료가 없는 영수증도 보여주지만, 조회기간·등록 범위가 다를 수 있으므로 이것만으로
  불공제를 확정하지 않는다.

### 전표에 미치는 영향

자료 업로드·연결은 전표나 공제세액을 자동 변경하지 않는다. 원문 세액, 홈택스 공제 표시,
영수증에서 검토한 공제세액을 구분해 보여준다. 신고서 부속서류의 거래처별 합계 차이로 개별
영수증 세액을 보정하던 동작은 제거했다. `일치`는 자료 대조 결과일 뿐 사업 관련성·공제 요건의
확정이 아니며, 취소·수정 거래는 원거래와 귀속기간을 별도로 확인한다.

## 거래별 AI 추천 근거

AI 계정 판단은 회사 안의 거래처 코드·고유 별칭·사업자번호와 확정 영수증의 은행 거래 연결을
따라 관련 확정 분개 및 이전 원장 사례를 찾는다. 적요·품목, 증빙 종류, 금액, 시기를 비교해
거래당 최대 8개 사례를 전달한다. 별도 그래프 DB나 임베딩 API 없이 요청마다 현재 자료로 검색한다.

- 미확정·제외·내부이체·영수증으로 이미 처리된 은행 행, 자기 자신과 같은 지급 거래,
  날짜가 확인되는 미래 사례는 검색에서 제외한다. 금액만 같은 거래는 근거로 선택하지 않는다.
- 같은 거래처라도 용도가 다르면 서로 다른 계정을 추천할 수 있다. 거래처별 다수결로 추천 계정을
  덮어쓰던 처리는 제거했다. 금액 검산·사용자 수정 보호·확정 조건은 기존 흐름을 따른다.
- 거래 분개 상세와 영수증 검토에서 **추천에 전달한 관련 사례**를 펼치면 당시 계정·금액·적요,
  선택 이유와 연결 경로를 확인할 수 있다. **현재 전표 확인**으로 현재 상태를 조회하고,
  영수증은 원본도 열 수 있다. 표시된 사례는 AI에 전달한 자료이며 모델이 모두 인용했다는 뜻은 아니다.
- 추천 당시 근거는 추천 결과와 함께 저장된다. 근거 전표를 삭제하거나 검토로 되돌리면 다음 검색에서
  제외되지만 이전 추천의 기록은 남는다. 기존 추천은 자동 재실행하지 않는다.
- 새로 가져오는 이전 원장은 파일명·시트·행 번호·원문 날짜를 보존한다. 추천 화면에는 사례당
  최대 5개 원본 행 위치를 표시한다. 연도나 입출금 방향이 없는 원장은 이를 추정하지 않는다.
  기존에 가져온 원장의 행 위치는 다시 가져와야 기록된다.

검색 회귀 테스트는 외부 AI 호출 없이 관계 연결, 검색 순위, 회사 분리, 근거 저장을 검증한다.
실제 모델의 계정 정확도·검토자 수정률·토큰 비용 개선은 별도 실거래 평가가 필요하다.

## 회계처리 정책 GraphRAG

**회사 기준 → 회계처리 정책 · GraphRAG**에서 정책 원문을 붙여 넣고 출처 문서명·원문 위치,
정책 식별명·버전·적용기간을 등록한다. 검색어, 계정, 입출금 방향, 증빙 종류, 금액 범위와
예외 검색어를 직접 검토한 뒤 **초안 저장 → 원문·조건 확인 후 승인**한다.
현재 버전은 텍스트를 직접 등록하며 PDF 자동 추출·임베딩 서비스·외부 그래프 DB를 사용하지 않는다.

- 검색은 `거래 → 검색 조건 → 승인 정책 → 계정 → 관련 확정 사례` 관계를 따라 원문과 사례를
  함께 AI에 전달한다. 검색어는 대소문자를 구분하지 않는 부분 문자열 OR 조건이고, 방향·증빙·금액은
  AND 조건이다. 거래일이 없으면 정책 버전을 추정하지 않는다. 정책 조건 일치는 실제 적용의 확정이 아니다.
- 정책은 회사별 SQL 테이블에 저장한다. 같은 정책 식별명의 버전은 중복될 수 없고, 승인 버전의
  적용기간은 겹칠 수 없다. 적용기간의 시작일·종료일을 포함한다. 승인·철회된 원문은 수정하지 않는다.
  개정은 새 버전으로 등록한다. 무기한 버전을 교체하려면 기존 버전을 철회하고, 필요한 과거 기간의
  버전도 별도로 등록·승인한다. 철회 버전은 이후 검색에서 제외한다.
- 거래마다 구체적인 검색 조건을 우선해 최대 4개 정책 조건과 기존 최대 8개 사례를 전달한다.
  추가 정책이 생략되거나 예외가 등록되어 있거나 세무 참고 정책이 조회되면 자동 확정을 보류한다.
  추천 계정과 정책·과거 사례가 충돌하는 경우에도 담당자가 검토한다. 세무 참고 정책은 기존 세액
  검산·공제 검토를 대신하지 않는다.
- 영수증·은행 분개 검토에서 **추천에 전달한 정책·관련 사례**를 펼치면 추천 당시 원문·버전·출처·조건·
  예외·연결 경로를 볼 수 있다. 이후 정책을 철회해도 기존 추천 근거는 보존한다. 정책 변경은 기존
  확정 전표를 자동 변경하지 않는다. 미확정 거래의 기존 추천에 반영하려면 해당 거래의 AI 추천을 다시 실행한다.
- 초안 저장·승인·철회는 회사 기준 저장과 독립적이다. 승인 정책이 참조하는 계정을 삭제하려면
  먼저 해당 정책을 철회한다.

정책 회귀 테스트: `cd backend` 후 `.\.venv\Scripts\python -m pytest tests/test_policies.py tests/test_retrieval.py -q`.
외부 AI 호출 없이 회사 격리·승인·버전·검색 조건·근거 저장·자동 확정 보류를 확인한다.

## 테스트와 빌드

백엔드 테스트는 외부 API를 호출하지 않으며, 합성 자료와 임시 DB를 쓴다.

```powershell
cd backend
.\.venv\Scripts\python -m pytest
```

특정 영역만 돌릴 때는 파일을 지정한다(예: `tests/test_hometax.py -q`).

`TEST_DATABASE_URL`을 지정하면 PostgreSQL에서 테스트한다. 테스트마다 표를 지우고 새로 만들므로
**실데이터가 있는 DB는 절대 지정하지 않는다.**

```powershell
$env:TEST_DATABASE_URL = "postgresql+psycopg://postgres@127.0.0.1:5432/journalizer_test"
python -m pytest
```

저장소 루트의 `test.cmd`는 백엔드 문법 검사와 프론트엔드 lint·build를 실행한다(pytest는 포함하지 않는다).

```cmd
test.cmd
```

프론트엔드만 확인할 때:

```powershell
cd frontend
npm run lint
npm run build
```

테스트만 건너뛴다.

  빈 페이지, 중복 분할본, ZIP은 두지 않는다.

  광주은행은 개별 PDF 172개다.
